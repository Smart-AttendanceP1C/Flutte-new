# Backend Real Inventory — source: `server.js` (authoritative), `authMiddleware.js`, `roleMiddleware.js`, `openapi.yaml` (contract reference)

Base URL (real, running, verified): `https://perry-lee-stay-firefox.trycloudflare.com`
- `GET /health` → 200 `{"success":true,"message":"Server and database are working"}` (verified live).
- Protected routes without token → 401 `{"success":false,"error":{"code":"UNAUTHORIZED","message":"Authorization token is required","request_id":"..."}}` (verified live on `/api/v1/courses`, `/api/v1/timetable`, `/api/v1/attendance/records/export`).
- `POST /api/v1/auth/login` with `{}` → 400 `VALIDATION_ERROR` (verified live); with unknown email → 401 `INVALID_CREDENTIALS` (verified live).
- Previous hosts replaced throughout; same contract verified on the new host. `openapi.yaml`/`server.js` route set unchanged (38 routes).
- Auth: `Authorization: Bearer <JWT>`. Login JWT payload `{userId, email, role}`, `expiresIn 2h`. QR JWT `{type:"attendance_qr", sessionId, secretVersion, generatedAt}`, `expiresIn 10s`. Scan ticket JWT `{type:"attendance_scan_ticket", sessionId, studentId}`, `expiresIn 30s`.
- Roles (real, from `roleMiddleware.js` + `server.js` usage): `student`, `lecturer`, `ta`, `admin`, `auditor`. 403 `FORBIDDEN` when role not allowed. There is NO `instructor`/`faculty`/`staff` role in the backend — UI labels "Instructor/Faculty" map to `lecturer`/`ta`.
- Envelope: success `{success:true, data:...}` (some include `filters`, `message`, `user`); errors `{success:false, error:{code, message, request_id?}}` (`request_id` injected via `X-Request-ID`).
- No telemetry, no location, no IP-based anything anywhere in `server.js`. No support/helpdesk endpoints. No logout endpoint (stateless JWT; logout = discard token client-side).

## Mismatches: `server.js` vs `openapi.yaml`
1. Server URL: `openapi.yaml` `servers[0].url` = `https://perry-lee-stay-firefox.trycloudflare.com` (current). Flutter uses the real URL.
2. `GET /api/v1/protected` (lecturer-only test route) exists in `server.js` (§TEST PROTECTED ROUTE) but is NOT documented in `openapi.yaml`. Not used by the app.
3. QR route comment in `server.js` says "GET MY ATTENDANCE SESSIONS" above `GET /attendance/sessions/:sessionId/qr`, but the handler generates/rotates the QR token — behavior follows the handler + `openapi.yaml` (`Generate the current rotating QR token`), not the comment.
4. `GET /attendance/records/export` in `server.js` allows roles `student, lecturer, ta, admin, auditor`; `openapi.yaml` documents the endpoint but the role list lives only in code — code is authoritative.
5. `openapi.yaml` `CorrectionRequest` requires `attendance_event_id + evidence` — matches `server.js`. No `course/reason/attachment` fields exist in the backend; UI form fields are mapped to `evidence` text, and the request must reference a REAL `attendance_event_id` from the student's attendance/Correction-`me` list (no invented IDs).
